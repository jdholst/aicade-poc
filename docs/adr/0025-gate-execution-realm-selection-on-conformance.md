# Gate execution-realm selection on conformance

Phase 9 will select its Mechanic Execution Realm technology only after a runnable candidate passes the Execution Realm Conformance Suite in Sparkline's real browser architecture. Any raw-engine or forbidden-authority access, representative escape, inability to terminate runaway code without freezing the editor, opaque-handle leak, cleanup failure, or loss of controlled deterministic execution is a hard rejection; source scanning alone is insufficient, while performance and implementation ergonomics only distinguish candidates that first pass every boundary gate.

## 2026-08-06 browser-session amendment

The public conformance contract is `mechanic_execution_realm_conformance/v3`. The runner accepts one opaque, single-run conformance session rather than independently supplied candidate and host values. `createMechanicExecutionRealmConformanceSession` supports candidate-neutral non-browser checks, but it cannot mint browser-admission evidence even when its candidate self-declares `environment: "browser"` or its host observes a genuine heartbeat.

Browser admission must prepare every candidate/runtime iframe with `prepareMechanicExecutionRealmBrowserConformanceIframe` while it is still disconnected and unloaded, then use `createMechanicExecutionRealmBrowserConformanceSession` and `mechanic_execution_realm_browser_session/v3`. Preparation sets the exact sandbox before first load and privately records the element; any later sandbox mutation permanently invalidates that registration, including a change that is reverted before capture. The trusted harness captures the prepared candidate endpoint and runtime iframe as distinct objects, generates the fixed private session, candidate-endpoint, and runtime identities, and sends each endpoint one ordered initialization message. The suite waits up to the separate fixed initialization bound for an exact runtime acknowledgement before starting probes. Per-probe challenges omit those identities, so an acknowledgement or response must use the endpoint's initialized identity rather than merely echoing caller-supplied challenge fields. Each candidate request and heartbeat receives a fresh cryptographic nonce. Every terminate request names the exact execute nonce it targets. Before returning a probe result, the candidate endpoint must send the execution acknowledgement for the exact execute request; a termination response cannot mint evidence without that prior acknowledgement. Only trusted `MessageEvent`s from the exact captured and still-current endpoint can mint the module-private, single-use evidence associated with that probe. Iframe evidence additionally requires the browser-reported event origin to be `"null"`. The runner atomically consumes the session before the suite and disposes it afterward; explicit disposal is also available for abandoned sessions.

Browser-session construction is transactional across both supplied endpoints. If owner-window resolution, runtime capture, candidate capture, nonce creation, or initialization fails, the factory discards every unclaimed candidate/runtime preparation supplied to that attempt, including an endpoint that control flow had not reached yet, and disconnects its observer. A rejected construction cannot leave preparation authority reusable by a later attempt. Trusted harnesses must not prepare relay or diagnostic iframes that will never be session-owned, and must explicitly dispose any prepared endpoint abandoned before calling the factory.

Trusted pre-load preparation is a public browser-admission precondition, so the conformance contract remains `mechanic_execution_realm_conformance/v3`. Correlating termination with the exact execute nonce changed the browser-session request wire shape from `mechanic_execution_realm_browser_session/v1` to `mechanic_execution_realm_browser_session/v2`; requiring the exact runtime-initialized acknowledgement changes it to `mechanic_execution_realm_browser_session/v3`.

The transactional cleanup correction completes the existing v3 lifecycle semantics without changing the public input shape, evidence contract, or wire messages, so the contract remains `mechanic_execution_realm_conformance/v3`.

Ticket 08 must:

1. Keep the whole-game runtime iframe separate from the Mechanic Execution Realm candidate. A candidate endpoint may be a dedicated sandboxed iframe or a host-owned Worker, but the selected technology remains replaceable behind the endpoint protocol.
2. Create each candidate/runtime iframe while disconnected, install its responder source, call `prepareMechanicExecutionRealmBrowserConformanceIframe`, and only then connect/load it. Do not mutate `sandbox` afterward. The session factory requires the private preparation record and the current normalized token set `{allow-scripts}`; it rejects an unprepared iframe, any sandbox mutation history, missing `allow-scripts`, every additional token including `allow-same-origin`, post-capture drift, and a trusted iframe response whose browser-reported origin is not `"null"`. Retagging an already-loaded iframe cannot establish the required sandbox. A successfully constructed session owns and disposes both preparation records, while any construction failure atomically releases every unclaimed preparation supplied to that attempt. If loading or setup is abandoned before construction, call `disposeMechanicExecutionRealmBrowserConformanceIframePreparation` for each prepared iframe; do not prepare relay or diagnostic iframes that are not intended for session ownership. Do not accept a caller-provided runtime or session ID as proof.
3. Implement the exported one-time initialization, candidate request/execution-acknowledgement/response, and runtime-heartbeat challenge/response protocol types. Install endpoint listeners before constructing the session, retain only the first initialized identity, send the acknowledgement immediately after the trusted endpoint dispatches an `execute` request, preserve the challenge's probe/action fields, and return the real probe result from the candidate endpoint. Never acknowledge `terminate` as execution evidence.
4. Pass the factory's opaque `session` directly to `runMechanicExecutionRealmConformanceSuite`. Do not pair a candidate adapter with an independently healthy iframe, translate evidence into booleans or structural receipts, or use `environment` metadata as admission evidence.
5. Require all unchanged 32 probes and ten hard gates to pass in the real browser path before comparing candidate performance or ergonomics.
