# Govern capabilities through one versioned registry

Sparkline will define the generated-mechanic capability surface in one versioned Mechanic Capability Registry that informs authoring types, runtime enforcement, generation constraints, deterministic evaluation, observations, and conformance tests. Capability gaps may motivate a new reusable primitive only after existing composition is ruled out and the operation is shown to be bounded, authorizable, deterministic, observable, isolatable, and worthwhile; generated code may report gaps but can never widen its own authority.
